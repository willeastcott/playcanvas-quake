# Development status and validation notes

This document records the port's implemented behavior, known gaps, and native-comparison history. For project setup and everyday commands, see [README.md](README.md).

## Project overview

An in-progress, source-faithful TypeScript port of the original 1996 Quake runtime to PlayCanvas. The current E1M1 vertical slice reads the original data formats directly; it does not substitute recreated textures, models, maps, or HUD art.

Demo brush entities use the recorded protocol snapshot, while the external BSP-model path explicitly excludes edict 0 so the map worldspawn cannot be overlaid as a second static copy. This keeps moving doors visibly synchronized with their sounds and recorded transforms.

## Run locally

Requirements: Node.js 22 or newer and a `tar` implementation that can extract LHA archives (the Windows `bsdtar` bundled with current Windows installations works).

```sh
npm install
npm run prepare:shareware
npm run dev
```

The console command `timedemo demo1` runs the original frame/seconds/fps benchmark over the supplied recording.

Open `http://127.0.0.1:5173` to run the verified `quake.rc` attract loop (`demo1`, `demo2`, `demo3`), start E1M1 with `?map=e1m1`, select another map with a query such as `?map=e1m2`, or play one original PAK demo with `?demo=demo1`. Click the game to capture the mouse and enable audio. Use WASD to move, Space or Enter to jump, Shift to run, the number keys or mouse wheel to select/cycle weapons through the original QuakeC impulses, Tab for the solo scoreboard, Escape for the original main menu, backquote for the console, Pause/Break to pause, F1–F5 for the supplied help/save/load/options/multiplayer menu shortcuts, F10 for the quit confirmation, and F12 to request a lossless 320×200 PNG screenshot. The supplied comma/period strafe and backslash mouse-look bindings are also retained alongside the additive WASD and wheel conveniences. The Single Player menu exposes the original 12-slot Load/Save screens using browser-local storage, Options → Customize controls exposes the original 18-action keys menu with keyboard, mouse-button, and wheel rebinding, and Multiplayer → Setup exposes the source-layout hostname, player name, and translated shirt/pants colors. Because this browser port has no network transport, Join and Start retain WinQuake's unavailable-network behavior and the menu displays `No Communications Available`. The console also accepts source-shaped `playdemo demo1`, `startdemos demo1 demo2 demo3`, `demos`, `stopdemo`, `save s0`/`load s0`, `bind`, `unbind`, and `unbindall` commands, including quoted bindings such as `bind x "+jump"`. Append `?debug=1` to show the non-original validation overlay with the live player origin, view angles, and pointer-lock/mouse-look state.

Web Audio is suspended whenever the game page becomes hidden or its window loses focus, so ambient sounds, effects, and optional supplied music cannot continue audibly in another browser tab. Returning to the visible game resumes only an audio context that the player had already enabled; an untouched autoplay-suspended context remains suspended until the game is clicked.

The 16:10 game stage responds to browser-tab and containing-pane resizes while preserving Quake's internal 320×200 compositor. Its percentage layout remains authoritative and only the PlayCanvas WebGL backing buffer is resized, preventing `AppBase.resizeCanvas` from freezing a previous tab size into inline pixel CSS. Particle point sizes continue to use the logical Quake view rectangle, so a larger browser framebuffer does not turn them into proportionally chunkier dots.

F6 and F9 now execute the supplied `echo …; wait; save/load quick` bindings. The browser-backed `quick.sav` is independent of the 12 menu slots, and `wait` defers the remainder of the command buffer until the next host frame as in `cmd.c`. The console `exec` command decodes scripts from the active PAK and inserts them ahead of buffered commands, including the supplied commented `default.cfg`; browser-local loose config files remain outside this PAK-backed data path.

F11 retains the supplied `zoom_in`/`zoom_out` aliases. Alias text is inserted ahead of the remaining command buffer, the staged FOV values advance one host frame per `wait`, the live PlayCanvas projection updates at each step, and the final binding and sensitivity return to `zoom_in` and `3` after zooming out. Console `alias` definitions use the same expansion path.

The F11 endpoint now has a native-matched lossless comparison. WinQuake clamps the alias's final `fov 5` to 10, and its software mip selection scales with `width / (2*tan(fov/2))`; applying that same FOV-aware projection scale and clipping to the browser's one-mip-per-surface path reduced the FOV-10 gameplay MAE/RMSE from 5.51/13.81 to 0.0079/0.3167, with a pixel-identical HUD and no change to the canonical FOV-90 spawn frame. The refreshed FOV-60 comparison likewise improved from gameplay 0.99/3.30 to 0.176/1.875, while a new upper-clamp FOV-170 comparison is 0.208/1.518 with the HUD still exact.

The default palette uses Quake's `gamma 1`. Append `?gamma=0.7` (values are clamped to 0.3-1.0), use the Options-screen Brightness slider, or enter `gamma <value>` in the console to rebuild the indexed palette live across the world, models, particles, and HUD with the original gamma-table formula. The original client mixer controls `bgmvolume`, `volume`, `ambient_level`, and `ambient_fade` are also live console cvars and survive the browser reload used for a level change or restart. The same applies to the source client-input, view, and compositor cvars, including `sensitivity`, the `m_*` and `cl_*speed` families, `lookspring`, `lookstrafe`, `v_centermove`, `v_centerspeed`, `cl_bob`, `cl_bobcycle`, `cl_bobup`, `cl_rollangle`, `cl_rollspeed`, `v_kicktime`, `v_kickroll`, `v_kickpitch`, the `v_i*cycle`/`v_i*level` idle controls, `v_idlescale`, `scr_ofsx`/`scr_ofsy`/`scr_ofsz`, `fov`, `crosshair`/`cl_crossx`/`cl_crossy`, `showpause`, `scr_conspeed`, `scr_centertime`, and `scr_printspeed`. As in WinQuake's `Cvar_Command`, assignments are silent and an argument-free cvar command prints the current value. The source `developer` cvar defaults to zero; QuakeC builtin 25 (`dprint`) concatenates all supplied strings and reaches the ordinary console/notify path only while `developer` is nonzero.

`prepare:shareware` downloads the historical Quake 1.06 shareware installer from the id Software FTP mirror, verifies both the archive and extracted `pak0.pak` by exact byte length and SHA-256, and stores the result under the gitignored `.quake-data/` directory. A legally owned compatible PAK can instead be placed at `.quake-data/id1/pak0.pak`.

The shareware PAK does not contain the original CD soundtrack. To enable music without redistributing it, place a legally obtained rip under `.quake-data/id1/music/` using the conventional `trackNN` name. E1M1's actual worldspawn requests track 6, so the accepted filenames are `track06.ogg`, `track06.mp3`, `track06.flac`, or `track06.wav`. The port loops the complete supplied track and otherwise remains silent; it never substitutes another recording.

No Quake game data is committed to this repository.

## Known gaps

This is not yet a complete Quake implementation. In particular:

- The supported supplied key bindings now reach their existing command paths, including F6/F9 quicksave/quickload. Multiplayer `messagemode` chat remains unimplemented because there is no network transport; it is not silently rebound to different behavior.
- QuakeC player/spawn/think/touch execution, registered cvar access, monster-expanded point-projectile impacts, source-gated and frame-timed collision touches, swept non-point entity collision, source `MOVE_NOMONSTERS` handling for nonsolid/trigger toss entities, exact `ED_Free` field clearing, toss/bounce landing stops, four-bump `MOVETYPE_STEP` freefall with fly/swim exemptions, hard-landing and liquid-transition sounds, translating-pusher occupant movement and blocked callbacks, player-eye PVS-gated `checkclient`, both of E1M1's authored tutorial-message/`killtarget` lifecycles, source-shaped monster chase selection, every active normal-skill E1M1 soldier's complete authored patrol loop, representative real-E1M1 soldier and dog combat, scheduled-think damage paths for knight, demon, ogre, wizard, shambler, and zombie, and Chthon's complete authored E1M7 encounter are implemented, but server physics and several builtins remain incomplete. `sv_gravity` now reaches player, step/toss/bounce, and particle physics, including an optional mod entity `gravity` multiplier for server movers; source-shaped vector validation sanitizes every exponent-255 NaN/infinity value and enforces live `sv_maxvelocity`. Two- and three-occupant E1M1 lift chains cover WALK/STEP/`SOLID_NOT` carrying, later-block rollback, and persistent corpse bbox collapse. A separate five-occupant chain carries four earlier `MOVETYPE_WALK` riders while a ceiling-clipped `SOLID_TRIGGER` takes its partial move and collapses to a point without rolling back the lift or prior riders, matching `SV_PushMove`'s special nonblocking branch. Complete monster combat/navigation behavior beyond these representative paths—including episode-wide alternate attack, pain, and death variants beyond the now-covered E1M1 dog's `dog_painb*`/`dog_dieb*` branches—has not been exercised, so full monster AI is not yet established as faithful.
- Pickups, one-shot secret counting/removal, monster `walkmove` trigger relinking, touch-trigger chains, stationary `force_retouch` overlap passes, collided inline-brush button dispatch, the real E1M1 three-button counter and message sequence, dynamic `SOLID_BBOX`/`SOLID_SLIDEBOX` player collision and touch dispatch, original E1M1 teleporter routing/effects/backstep suppression, its shootable explosive box, its one-health `t4` shootable-trigger door, and translating button/door motion work, but the map's remaining multi-entity interaction paths still need broader validation. The app applies the client command's acceleration/friction phase before the server frame, then delegates gravity and position integration after server-side `PlayerPreThink`, scheduled think, and velocity validation but before collision touches and `PlayerPostThink`; this preserves the original pre-friction jump-frame ordering without duplicating QuakeC jump velocity or sound. As in `SV_ClientThink`, living fly, noclip, toss, and bounce clients still process their command vector: vertical input survives outside walk mode, noclip replaces velocity with the clamped wish vector, and the air basis uses the source player-model pitch, yaw, punch, and movement roll. Toss/bounce players retain independent entity angles, advance `avelocity`, stop both velocities on landing, and run the source collision-triggered liquid-transition path. The base `FL_WATERJUMP` branch also locks horizontal velocity to QuakeC `movedir`, honors its two-second safety timer, suppresses gravity, and disables step-up while active. Non-client push/none/noclip/step/toss physics and live forced retouches run in edict order. A zero-displacement fly frame still follows `SV_PushEntity` through tracing and relinking, so overlapping triggers touch even without linear motion. Player motion still uses the client controller's combined BSP/entity sweeps rather than the original server's exact client-physics functions, so the movement implementation remains approximate even though the major host-loop phases are source ordered.
- Alias entities use QuakeC-selected discrete poses, matching the original software renderer rather than adding non-original pose interpolation. Cumulative grouped-frame and grouped-skin timing is supported; `ST_RAND` uses a stable platform-independent 0–1 second offset because the historical C-runtime random sequence is not portable. Invalid MDL frame/skin and SPR frame indices now follow `R_AliasSetupFrame`, `R_AliasSetupSkin`, and `R_GetSpriteframe` back to index zero instead of incorrectly clamping to the last entry. World aliases and the viewmodel use recursive BSP light sampling, animated lightstyles, dynamic-light boosts, the original ambient/shade clamps, the unrenormalized 162-entry Quake MDL normal table, integer vertex-light values, affine screen-space skin/light interpolation, and the original indexed colormap grades. Viewmodel, monster, projectile, beam, and gib appearances have native screenshot baselines; broader animation states and exact software triangle coverage remain incomplete. SPR v1 ordinary-frame rendering is exercised directly by native-matched rocket, grenade, and authored explosive-box `s_explod.spr` captures plus the real drowning chain's `s_bubble.spr` frames 0 and 1. The verified shareware PAK's three sprites are all view-parallel and contain no grouped frames, so grouped sprites, transparency edge cases and the remaining orientation modes still need broader visual validation; a synthetic source-layout regression proves grouped SPR parsing and cumulative interval selection without presenting it as original-data visual evidence.
- Indexed particles, all original MDL-flag trail classes, rotating pickups, source-derived dynamic-light accumulation, and the four original beam message variants are present. QuakeC particles and temporary effects round-trip coordinates, directions, counts, and colors through their original packet widths. Server-emitted particle and temporary-entity messages are consumed in write order after server physics and before entity relinking/effects; the particle renderer is attached before capture warmups, so those calls consume their random values at the frame in which the source client would parse them. Ordinary impacts, explosion-two, blob, lava, and teleporter constructors consume randomness in the exact `r_part.c` lifetime/color/origin/velocity order; focused tests use distinct values for every call so an object-property reordering cannot silently change the stream. Beams retain the source's entity-keyed 0.2-second lifetime, 24-beam state limit, 64-segment render limit, 30-unit MDL spacing, full pitch/yaw/roll transform, and player-origin refresh. The verified shareware PAK includes the three lightning bolt MDLs but not the optional `progs/beam.mdl`; that variant is therefore rendered only when supplied by a compatible legal PAK, with no substitute asset. Particle and beam-roll random sequences remain platform-independent rather than tied to a historical C runtime. Dynamic lights use Quake's BSP-plane projection, lightmap-texel distance metric, 8.8 accumulation, and full 0–65,280 colormap range for map faces. Inline and instanced brush-model behavior retains the original software renderer's model-coordinate limitations rather than adding non-original light transforms. BSP lighting converts every static and dynamic sample to the source's clamped 8.8 darkness value and uses the software surface cache's directional integer interpolation inside mip-sized blocks; replicated atlas gutters prevent adjacent-face sampling. Each clipped BSP face now receives WinQuake's single `nearzi * scale_for_mip * mipadjust` mip decision, and that explicit mip drives both the original texture level and the light-interpolation block size. World-surface GPU triangle coverage and perspective interpolation still do not reproduce every software edge/span step.
